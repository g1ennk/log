# 260723 기술 면접 회고

## 개요

- 회사: 초기 스타트업
- 형식: 백엔드 엔지니어 2명과 진행
- 진행: 이력서 기반 질문, 실시간 경매 시스템 설계, 컬처핏, 역질문
- 체감 난이도: 7/10
    - 서류 전 영역을 넓게 확인했다.
    - 단순 정의가 아닌 동시성, 메시지 유실, 장애 등 가상 상황까지 깊게 물었다.
    - 라이브로 시스템 설계는 처음이었고, 이에 대한 대비가 없었다.
    - 과제 중심 면접으로 안내받았지만, 실제로는 과제 질문이 단 하나도 없었다.

## 면접 흐름

### 1. 오프닝과 회사 이해

- 자기소개
- 회사 서비스에 대해 알아본 내용
- 회사와 서비스에 대해 궁금했던 점

### 2. 이력서 기반 질문

- Terraform state locking, 동시 apply 사고, 협업 중 Terraform 이슈
- Terraform state에 저장되는 secret 관리
- Access Token을 localStorage에 두지 않은 이유
- Refresh Token을 HttpOnly cookie에 둔 이유와 cookie의 위험
- 멀티디바이스 로그인 해제 정책
- 같은 기기 여러 탭의 동시 refresh
- 만료된 RT와 폐기된 RT 재사용의 차이
- `@Transactional`, rollback, self-invocation, `REQUIRES_NEW`
- Redis Pub/Sub 유실과 재진입 시 snapshot 복구
- 구독과 snapshot 조회 순서
- Kafka, Redis Streams 대신 Pub/Sub을 선택한 이유
- Timer 최초 INSERT 경로의 InnoDB deadlock
- GCP 단일 VM의 사양과 용량 판단 근거
- Docker layer cache와 빌드 시간 단축
- Kubernetes namespace 간 통신
- 단일 control plane 장애와 worker의 동작
- control plane 장애 중 Pod 장애 처리

### 3. 실시간 경매 시스템 설계

- 요구사항을 받으면 어디서부터 시작할지
- 도메인 모델과 경매 흐름
- 1만~2만 명 동시 입찰 시 문제
- 동시성 제어와 현재 최고가 갱신
- 마감 1초 전 2만 건 요청이 들어온 경우
- 마감 이후에도 처리가 이어질 때 사용자에게 보여줄 상태
- 서버가 어느 요청까지 유효하게 처리할지
- Kafka 같은 추가 인프라 없이 최고가를 구할 자료구조

### 4. 컬처핏

- 요구사항과 설계가 자주 뒤집히는 스타트업 환경 대응
- 한 달 기한 프로젝트에서 동료의 생산성이 현저히 낮은 경우
- 개발 조직 구성에 대한 역질문

## 회고

### 1. 준비 방향이 실제 면접과 달랐다.

사전에 과제 전형에 관한 이야기로 면접을 진행했다고 전달 받았고, 과제에 최대한 포커스를 맞춰 과제 구현 내용과 선택 근거를 설명하는 데 많은 시간을 투입했다. 그러나 실제 면접에서는 사전 과제에 관한 질문은 하나도 나오지 않았다.

실제 검증 대상은 다음과 같았다.

- 이력서와 포트폴리오에 적은 내용을 얼마나 정확히 이해하고 있는가.
- 기존 프로젝트의 정상 흐름뿐 아니라 동시성, 장애, 보안, 재진입 같은 실패 흐름도 설명할 수 있는가.
- 처음 받는 백엔드 시스템 설계 문제를 면접관과 티키타카하며 구체화할 수 있는가.

면접 준비 시 과제에 포커스를 맞춘 건 큰 문제는 아니지만, 다른 것에 대한 대비를 과제에 비해 덜 한 건 완전히 판단 미스였다. 앞으로는 과제 뿐만 아니라 서류 내용 숙지와 백엔드 기본기와 시스템 설계 준비가 필요해 보인다.

### 2. 첫 면접에서 현재 위치를 파악했다.

이번 면접이 첫 회사 기술 면접이었다. 단순히 머리와 문서로 내용을 정리하는 것과 실제 면접관 앞에서 질문을 듣고, 의도를 파악하고, 즉석해서 구조화해 답하는 과정은 완전히 다른 이야기였다.

이번 면접은 명백히 준비 부족과 역량 부족이었다고 판단한다.

- 준비 부족: 이력서와 포트폴리오의 내용을 머리로만 이해하고, 실제 발화에 대한 대비를 하지 못했다.
- 역량 부족: 1년이 넘은 경험이라 Kubernetes의 기본 개념 및 동작, Terraform 등 서류에 있는 내용 뿐만 아니라 관련 기본적인 개념은 숙지하거나, 자신이 없다면 아예 서류에서 제외하는 것도 고려해봐야 한다.
- 발화 부족: 알고 있는 개념도 이를 논리적이고 구조적으로 명확하게 전달하지 못했다.

### 3. 다음으로

1. 이력서와 포트폴리오를 꼬리 질문에도 방어할 수 있을 정도로 깊게 판다.
2. 백엔드 기본기, 인프라, 동시성, 인증, 네트워크 등을 관련 CS 개념과 프로젝트를 연관지어 공부한다.
3. 시스템 설계에 대한 연습이 필요하다.
4. 머리나 문서로만 정리하는 것이 아닌 실제로 면접 환경처럼 구성해 연습한다.
5. 답을 외우는 것보단 각각의 질문에 어느정도 포멧을 적용해 실제 면접에서도 당황하지 않고 구조화된 답변을 할 수 있도록 연습한다.
