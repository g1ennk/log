# 260724 기술 면접 회고

## 개요

- 회사: 에듀테크 스타트업, 백엔드 개발자 포지션, 육아휴직 대체 계약직
- 형식: 개발자 2인과 40분간 진행
- 진행: 자기소개 -> Java,Spring 기본기, 서류 관련, 테스트 및 운영, AI 활용, 컬쳐핏과 근무 조건
- 체감 난이도: 5/10
    - 직전 면접에 부족한 부분을 보강해서 서류 관련해선 나름 잘 답변함.
    - 다만, 기본적인 Java 및 Spring 관련 개념을 물어봤고, 이에 대해 완벽한 대비는 안됐었음.
        - 좀 더 간결하고 정확하게 말할 수 있어야 한다.

## 면접 흐름

### 1. 오프닝과 지원 동기

- 지원 포지션과 신입 여부 확인
- 자기소개
- 지원 동기

### 2. Java, Spring 기본기

- REST API
- 가장 자신 있는 언어와 Spring 경험
- IoC와 DI
- DispatcherServlet
- Primitive Type과 Reference Type
- 두 타입의 Memory 배치
- GC와 Collector 종류

### 3. 프로젝트 관련

- SSE 연결이 60초에 끊긴 원인을 HTTP 연결 관점에서 설명
- 만료된 AT로 세 API를 동시에 호출할 때 Client와 Server 동작
- 만료된 AT로 Resource API를 호출했을 때의 응답
- 단위 테스트와 통합 테스트의 사용 기준
- k6 부하 테스트의 목표와 동시 사용자·처리량 기준
- 인증 구조 4단계와 네 종류 토큰 분리 이유

### 4. NE:MO 팀 프로젝트와 문제 해결 방식

- NE:MO에서 맡은 역할
- 사용한 Cloud Platform
- 문제가 풀리지 않을 때 접근 방식
- AI가 제시한 선택지를 검증하는 기준
- 기술 선택 시 가장 중요하게 보는 조건

### 5. 운영 관련 질문

- 특정 API 응답 시간이 평소보다 3배 증가했을 때 조사 순서
- 일부 사용자가 이유 없이 로그아웃됐다고 신고했을 때 확인할 내용

### 6. 컬처핏과 근무 조건

- 경영학 전공에서 개발자로 전환한 계기
- 입사 후 어떤 개발자로 성장하고 싶은지
- 개발자로서 강점과 보완점
- 원격근무 환경 가능 여부
- 회사의 Full-Stack 성장 방향과 월 1회 대전 출근 안내
- 개발팀 규모와 결과 안내

### 7. 회사 측 설명

- Backend나 Frontend로 입사해도 장기적으로 Full-Stack 역량을 갖추는 방향을 지향한다.
- 평소에는 원격근무하며 Metaverse 협업 Platform을 이용한다.
- 월 1회 대전에 모여 회의, Refactoring과 기술 학습 등을 진행한다.
- 휴직자를 포함한 개발 인력은 6명이라고 안내했다.
- 다른 지원자의 면접이 진행 중이며 결과는 빠르면 다음 주 중 안내할 예정이라고 했다.

## 회고

### 1. 프로젝트 방어는 이전보다 좋아졌다

직전 면접과 비교하면 서류에 적은 프로젝트를 방어하는 능력은 확실히 나아졌다.

다만 내용을 알고 있는 것과 명확하게 전달하는 것은 엄연히 달랐다. 답변하면서 기억을 탐색하다 보니 결론에 도달하기 전의 생각이 그대로 노출됐고, 면접관 입장에서는 핵심이 선명하게 들리지 않을 수 있다. 앞으로는 답변을 구조화해서 문제 -> 원인 -> 해결 -> 검증 -> 한계 등의 포맷을 확실히 정해 더 짧지만 깔끔하게 얘기할 수 있어야 한다.

### 2. Backend 기본기를 더 공부해야 한다

이번 면접에서는 너무 흔히 물어보는 REST, IoC, DI, DispatcherServlet, Java 타입, GC처럼 백엔드 기본 개념을 확인했다. 이 개념들은 이전에 다 공부했었지만 정확하게 말하는 데 부족함이 있다고 느꼈다.

만약 대면 면접이었다면 더 크게 흔들렸을 가능성이 농후하다. 앞으로는 정확하게 질문의 의도를 확실하게 파악하고, 어떻게 말할지 생각 후 확실하게 발화하는 연습이 필요해 보인다.

### 3. AI Debugging 표현은 위험했다

어떤 문제가 발생했을 때 어떠한 방식으로 디버깅하고 문제를 해결하는지 물어보는 질문이 있었는데, 요즘은 확실히 내가 디버깅하는 것보단 에이전트 디버깅이 더 효율적이고 확실하다보니 AI를 적극적으로 활용해서 나만의 방식으로 해결한다는 느낌으로 답변했는데, 이는 면접관에게 "지원자는 무엇을 판단하고 책임지는지"라는 의문을 줄 수 있다.

앞으로는 AI를 적극 활용하지만 판단 기준과 검증 루틴 그리고 최종 책임은 내가 진다는 방식으로 답변해야 한다.

### 4. 머릿속 흐름을 그대로 말하지 않아야 한다

답변 자체가 완전히 틀리지는 않았다. 다만 생각의 흐름이 정리되지 않은 채 이야기한 경우가 많았다. 앞으로 다음과 같이 구조화된 답변을 활용해서 연습해야겠다.

- 기술 질문: 결론 -> 핵심 원리 -> 프로젝트 근거 -> 현재 한계
- 장애 경험: 증상 -> 원인 -> 해결 -> 검증
- 운영 상황: 영향 확인 -> 메트릭 -> 로그 및 트레이스 -> 즉시 완화 -> 원인 수정 -> 재검증

앞으로의 과제는 이미 이해하고 알고 있는 내용을 질문의 범위에 맞춰 짧고 논리적으로 답변하는 것이다.

### 5. 다음으로

1. Java·Spring 기본 개념을 20초 안에 정확히 말하는 연습을 매일 한다.
2. 질문이 직접 묻는 결과부터 먼저 답하고, 전체 흐름은 요청받을 때만 확장한다.
3. 구현에서 보장하는 범위와 보장하지 못하는 범위를 코드 기준으로 구분해서 말한다.
4. 테스트·부하 테스트 경험은 수치만이 아니라 목표, 조건, 한계까지 함께 설명한다.
5. AI 활용은 "AI가 더 잘한다"가 아니라 판단·검증과 최종 책임은 본인에게 있다는 식으로 표현한다.
6. 준비한 역질문을 실제 면접에서 놓치지 않고 사용한다.
