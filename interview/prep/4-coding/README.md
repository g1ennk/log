# 4. 라이브 코딩

화면 공유하고 실시간으로 문제 푸는 유형. 정답보다 풀어가는 과정이 보이는 게 중요하다.

## 포맷

문제 이해 → brute force → 최적화 → 구현 → 테스트

막혀도 침묵하지 말고 지금 무슨 생각을 하고 있는지 계속 말로 뱉는다. 최적해가 안 떠올라도 일단 brute force부터 말하는 게 가만히 있는 것보다 훨씬 낫다.

글은 줄글이 아니라 아래처럼 라벨을 달아서 쓴다.

## 예시 — "배열에서 두 수를 더해 target이 되는 인덱스 쌍 찾기"

- 문제 이해: 음수 포함 여부, 답이 여러 개면 하나만 반환하면 되는지 확인한다.
- brute force: 이중 for문으로 모든 쌍을 비교하면 O(n²).
- 최적화: 값을 순회하면서 `target - 현재값`을 해시맵에 기록해두면 O(n)에 풀 수 있다.
- 구현: 위 해시맵 방식으로 코드를 짠다.
- 테스트: 빈 배열, 쌍이 없는 경우로 검증한다.
