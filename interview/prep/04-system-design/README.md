# system-design

"URL 단축기 설계해보세요" 같은 질문. 신입 면접에도 가볍게 나오는 편이다.

## 포맷

요구사항 확인 → 개략 설계 → 상세화 → 트레이드오프

요구사항 확인은 **내가 면접관에게 질문하는** 단계다. 나머지 세 단계는 내가 말하고 면접관이 파고든다.

설계로 끝내지 않고 스펙 문서와 구현까지 이어간다 — 스펙과 코드는 `~/projects/sd-practice/<slug>`에 둔다.

## 질문 축

요구사항 확인 단계에서 던질 질문의 정본. 문제가 바뀌어도 축은 그대로다 — 외울 건 개별 질문이 아니라 이 순서다.

- **범위** — 어떤 기능이 필수인가, 이번에 안 다뤄도 되는 건 무엇인가
- **규모** — 사용자·요청·데이터가 얼마나 되는가, 피크와 평균의 차이는
- **정합성** — 틀리면 안 되는 것은 무엇인가, 잠깐 어긋나도 되는 것은
- **지연** — 어디까지 실시간이어야 하는가
- **제약** — 기존 시스템·팀·기한 중 설계를 묶는 것이 있는가
