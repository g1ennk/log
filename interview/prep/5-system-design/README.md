# 5. 시스템 설계

"URL 단축기 설계해보세요" 같은 질문. 신입 면접에도 가볍게 나오는 편이다.

## 포맷

요구사항 확인 → 개략 설계 → 상세화 → 트레이드오프

바로 그리지 말고 트래픽 규모나 필요한 기능부터 확인하고 시작한다. 다 깊게 파려고 하지 말고 1~2곳만 골라서 들어가는 게 낫고, 결국 평가받는 건 완벽한 설계가 아니라 트레이드오프를 설명할 수 있는지다.

글은 줄글이 아니라 아래처럼 라벨을 달아서 쓴다.

## 예시 — "URL 단축기 설계해보세요"

- 요구사항 확인: 트래픽 규모, 커스텀 URL 필요 여부를 먼저 확인한다.
- 개략 설계: 클라이언트 → API 서버 → (원본 URL DB + 짧은 키 생성) → 리다이렉트. 자주 조회되는 URL은 캐시로 부하를 줄인다.
- 상세화: 짧은 키 생성 방식 — 자동 증가 ID를 Base62로 인코딩하는 방식은 단순하지만 다음 값 유추가 가능하고, 랜덤 문자열은 유추는 어렵지만 충돌 체크 비용이 든다.
- 트레이드오프: 트래픽 규모와 보안 요구 수준에 따라 둘 중 하나를 고른다.
