# HashMap의 내부 동작 방식(해시 버킷, 트리화)을 설명해주세요

## 1. 요약

### 1.1. 결론

HashMap은 키의 해시코드를 기반으로 저장 위치(버킷)를 계산해 평균 O(1)의 조회 성능을 제공하는 자료구조입니다.

### 1.2. 왜

키-값 데이터 저장 시 배열이나 리스트를 사용하면 원하는 키를 찾기 위해 저장된 모든 원소를 순회해야 하므로 데이터가 많아질수록 조회 성능이 선형으로 나빠집니다. HashMap은 이러한 문제를 해결하기 위해 키를 정수값으로 변환하는 해시 함수를 이용해 데이터가 저장될 위치를 미리 계산하고, 조회 시에도 같은 계산으로 곧바로 위치를 찾아가는 방식을 사용합니다.

### 1.3. 원리

HashMap은 키 저장 시 key.hashCode()를 보조 해시 함수로 한 번 더 가공한 뒤, 그 값을 배열 길이로 나눈 나머지로 버킷 인덱스를 정합니다.
만약 서로 다른 키가 같은 버킷에 배치되는 해시 충돌이 발생하면 그 안의 항목들은 연결 리스트로 관리하는데, 자바 8부터는 하나의 버킷에 8개 이상 쌓이고 전체 배열 크기도 충분히 크다면 해당 버킷을 레드-블랙 트리로 변환해 최악의 경우에도 O(log n) 성능을 보장하도록 개선하였습니다.

### 1.4. 장단점 및 실무

실무에서는 최종 데이터 크기를 예측할 수 있는 경우 초기 용량을 지정해 리사이징 횟수를 줄이고, 해시 충돌을 줄이기 위해 hashCode를 고르게 분산되도록 재정의하는 것이 HashMap의 성능을 안정적으로 유지하는 데 중요하다고 생각합니다.
