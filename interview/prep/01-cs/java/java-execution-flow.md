# 자바 실행 흐름

## 1. 요약

### 1.1. 결론

자바 프로그램의 실행 흐름은 소스 코드가 바이트코드로 컴파일된 뒤, JVM이 이를 메모리에 적재하고 실행 엔진이 기계어로 바꿔 실행하는 과정을 말합니다.

### 1.2. 왜

자바는 OS나 CPU에 종속되지 않고 어디서든 실행되기 위해 이 과정을 JVM이라는 중간 계층을 거치도록 설계했습니다.

### 1.3. 원리

`javac`가 .java 소스를 바이트코드로 컴파일하면 `클래스 로더`가 필요한 시점에 이를 JVM 메모리에 적재하고, 실행 엔진이 기계어로 변환합니다. 이때 한 줄씩 해석하는
`인터프리터`와 자주 실행되는 핫스팟 코드를 통째로 컴파일해 캐시하는 `JIT 컴파일러`를 함께 사용합니다.

### 1.4. 장단점 및 실무

이 덕분에 짧은 작업은 인터프리터로 빠르게 시작하고, 오래 실행되는 서버는 JIT 최적화로 점점 빨라집니다. 다만 JIT는 워밍업이 필요해 초기엔 느릴 수 있어, 서버리스처럼 워밍업 시간이 부족한 환경에서는 GraalVM 같은 AOT 컴파일이 대안으로 검토됩니다.
