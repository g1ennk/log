# 다형성이란 / 왜 필요한가

## 1. 요약

### 1.1. 결론

다형성은 하나의 타입으로 여러 실제 타입의 객체를 다루되, 실행 시점에 각 객체에 맞는 동작이 실행되는 성질입니다.

### 1.2. 왜

객체마다 타입을 확인하고 분기해서 처리하면 새로운 타입이 추가될 때마다 그 분기 코드를 찾아 수정해야 합니다. 다형성은 부모 타입 또는 인터페이스의 메서드 호출 시 실체 객체 타입에 맞는 동작이 자동으로 실행되도록 해 이러한 문제를 해결합니다.

### 1.3. 원리

주로 자식 클래스가 부모의 메서드를 같은 시그니처로 재정의하는
`오버라이딩`으로 구현되며, 실제로 어떤 메서드가 실행될지는 런타임에 객체의 실제 타입을 보고 결정되는 동적 바인딩으로 동작합니다. 이와 달리 매개변수 타입으로 메서드를 구분하는
`오버로딩`은 컴파일 시점에 정적으로 결정된다는 점에서 차이가 있습니다.

### 1.4. 장단점 및 실무

실무에선 다형성으로 인해 새로운 타입을 추가할 때 기존 호출부 코드를 전혀 수정하지 않고 새 클래스만 추가하면 되도록 설계할 수 있고, 이는 개방-폐쇄 원칙을 지키는 코드를 작성하는데 핵심적인 역할을 했습니다.
