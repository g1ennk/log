# 스레드 풀이란

## 1. 요약

### 1.1. 결론

스레드 풀은 스레드를 미리 생성해두고 재사용하는 방식으로 작업을 처리하는 자료구조입니다.

### 1.2. 왜

요청마다 스레드를 새로 만들고 종료하는 방식은 생성과 소멸 비용이 너무 커서 트래픽이 너무 많은 서버 환경에서는 실제 작업 처리보다 스레드 관리에 자원을 더 많이 쓰게되는 문제가 있습니다.

### 1.3. 원리

스레드 풀은 스레드를 미리 만들어두고 작업이 끝나면 종료 대신 풀로 반환해 다음 작업에 재사용하는 방식으로 이러한 문제를 해결합니다. 덕분에 스레드 생성 및 소멸 비용 및 오버헤드를 줄이고, 동시에 실행되는 스레드 수를 제한해 자원 고갈을 방지할 수 있으며, 작업을 큐에 넣고 분배하는 로직을 ExecutorService 같은 구현체에 위임해 병렬 처리 코드를 단순하게 작성할 수 있습니다. 따라서 톰캣과 같은 WAS도 이런 이유로 클라이언트 요청 처리에 스레드 풀을 기본으로 사용합니다.

### 1.4. 장단점 및 실무

풀 키기는 작업이 CPU 연산 위주인지, I/O 대기가 많은지에 따라 다르게 설정해야 하는데, 외부 API 호출처럼 대기 시간이 긴 작업에는 더 큰 풀 크기를, CPU 연산이 많은 배치 작업에는 코어 수에 가까운 풀 크기를 적용해 처리량을 최적화해야 합니다.
