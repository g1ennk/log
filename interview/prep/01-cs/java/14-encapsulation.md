# 캡슐화란 / 왜 중요한가

## 1. 요약

### 1.1. 결론

캡슐화는 객체의 데이터와 그 데이터를 다루는 로직을 하나로 묶고, 외부에는 필요한 부분만 공개해 내부 구현을 감추는 것입니다.

### 1.2. 왜

만약 필드가 외부에 그대로 노출되어 있으면 다른 코드가 검증 없이 객체의 상태를 직접 바꿀 수 있어 객체가 스스로 일관성을 보장할 수 없다는 문제가 있었고, 캡슐화는 이러한 필드를 private으로 감추고 public 메서드를 통해서만 상태에 접근하도록 강제해 이러한 문제를 해결합니다.

### 1.3. 원리

이를 통해 값을 설정하기 전 유효성을 검증하거나 상태 변경 시 필요한 부수 처리를 객체 내부에서 보장할 수 있고, 내부 구현 방식이 바뀌어도 공개된 메서드 시그니처만 유지하면 이 클래스를 사용하는 외부 코드는 전혀 영향을 받지 않습니다.

### 1.4. 장단점 및 실무

단, 모든 엔티티 혹은 필드에 기계적으로 getter와 setter를 붙이는 건 피하고, 상태를 바꿔야 하는 메서드는 의미있는 이름으로 만들어 상태 변경 로직 자체를 캡슐화하는 방식을 많이 사용합니다.
