# String 객체는 가변일까요, 불변일까요? 그렇게 생각하신 이유도 함께 설명해 주세요.

## 1. 요약

### 1.1. 결론

String 객체는 불변 객체입니다.

### 1.2. 왜

String은 문자 데이터를 담는 내부 필드(char[], byte[])가 final로 선언되어 있고 이 안을 수정하는 메서드가 존재하지 않기 때문에, substring이나 concat 같은 메서드를 호출해도 원본은 유지하되 항상 새로운 String 객체를 반환합니다.

### 1.3. 원리

이처럼 String을 불변으로 설계한 이유는 자바가 문자열 리터럴을 String Constant Pool에서 재사용하기 때문입니다. 같은 값의 리터럴은 풀 안의 객체를 공유하는데, 만약 String이 가변이었다면 하나가 바뀌는 순간 같은 값을 참조하던 모든 변수에도 영향을 끼치는 부작용이 발생했을 것입니다. 하지만 이처럼 불변으로 설계해 여러 스레드가 동시에 문자열을 참조해도 안전하고, 방어적 복사 없이 그대로 값을 공유할 수 있습니다.

### 1.4. 장단점 및 실무

다만 반복문처럼 문자열을 계속 이어 붙이면 매번 새로운 객체가 생기고 이전 객체는 GC 참조 대상이 되지 않아 GC 부담이 커지므로, 이처럼 반복적인 문자열 작업에는 가변 버퍼를 내부에 유지하는 StringBuilder를 사용해 불필요한 객체를 피하는 방법도 있습니다.
