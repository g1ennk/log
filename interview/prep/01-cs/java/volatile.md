# volatile 키워드의 역할은?

## 1. 요약

### 1.1. 결론

volatile은 변수의 값을 항상 메인 메모리에서 읽고 쓰도록 강제해 가시성을 보장하고, 해당 변수 접근 전후의 명령어 재정렬도 제한하는 키워드입니다.

### 1.2. 왜

멀티코어 CPU는 변수 값을 코어별 캐시에 복사해 연산하기 때문에, 한 스레드가 값을 바꿔도 다른 스레드가 메인 메모리의 최신 값을 즉시 못 볼 수도 있습니다.

### 1.3. 원리

volatile로 선언 시 모든 읽기, 쓰기가 메인 메모리를 걸쳐 최신 값이 즉시 보이고, 컴파일러와 CPU가 그 변수 접근 기준으로 앞뒤 명령어 순서를 재배치하지 못하게 막습니다.

### 1.4. 장단점 및 실무

다만 count++처럼 읽고->계산하고->쓰는 복합 연산의 원자성까지는 보장하지 않아 경쟁이 생길 수 있습니다. 따라서 종료 플래그처럼 한 스레드만 쓰는 경우에는 volatile을, 원자성이 필요한 카운터에는 synchronized나 AtomicInteger를 선택하는 것이 효율적이라고 생각합니다.
