# 데이터베이스 인덱스에 대해서 설명해주세요.

## 1. 요약

### 1.1. 결론

인덱스는 자주 검색하는 컬럼 값을 미리 정렬해 둔 별도의 자료구조로, 테이블 전체를 훑지 않고도 원하는 데이터 위치로 빠르게 찾아가게 해주는 장치입니다.

### 1.2. 왜

인덱스가 없으면 조건에 맞는 데이터 검색을 위해 첫 행부터 끝 행까지 훑는 풀 테이블 스캔을 해야 하고, 이는 데이터가 수백만 건으로 늘어나면 디스크 I/O가 폭증해 응답이 급격히 느려지기 때문에 등장했습니다.

### 1.3. 원리

MySQL InnoDB는 인덱스를 B+Tree로 구현해 루트 -> 브랜치 -> 리프 노드로 내려가며 값의 크기를 비교하므로, 데이터가 아무리 많아도 트리 높이만큼만 탐색하면 됩니다. 실제 데이터 주소는 리프 노드에만 두고 리프끼리 연결 리스트로 이어 두어, 범위 검색에서도 시작 리프만 찾으면 옆으로 쭉 읽어나갈 수 있습니다.

### 1.4. 장단점 및 실무

이는 정렬 상태를 유지해야 해서 INSERT, UPDATE, DELETE 시마다 인덱스도 함께 갱신되어 쓰기 성능이 희생되고 저장 공간도 차지하므로, 조회가 잦고 카디널리티가 높은 컬럼에 선별적으로 거는 것이 원칙입니다. 또한 읽어야 할 데이터가 전체의 20-25%를 넘으면 랜덤 I/O가 누적되는 인덱스 스캔보다 순차 I/O의 풀 테이블 스캔이 더 빠를 수 있어, 이는 옵티마이저가 그 손익을 계산해 인덱스를 무시하기도 합니다.
