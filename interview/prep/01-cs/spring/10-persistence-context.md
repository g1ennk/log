# 영속성 컨텍스트의 1차 캐시·쓰기 지연·변경 감지는 어떻게 동작하나요?

## 1. 요약

### 1.1. 결론

영속성 컨텍스트는 엔티티를 관리하는 논리적 공간으로, 1차 캐시/쓰기 지연/변경 감지로 DB와의 반복 작업을 자동화합니다.

### 1.2. 왜

JDBC로 직접 다루면 조회 시마다 DB에 접근해야 하고, 수정 시마다 UPDATE 쿼리를 작성해야 하기에, JPA는 이러한 반복 작업을 줄이기 위해 엔티티를 메모리에서 관리하는 중간 계층을 두었습니다.

### 1.3. 원리

1차 캐시는 식별자를 키로 엔티티를 저장해 같은 트랜잭션 안 재조회 시 DB 접근 없이 반환합니다.
쓰기 지연은 INSERT, UPDATE 쿼리를 모아뒀다가 커밋 시점에 한 번에 반영합니다.
변경 감지는 조회 시점 스냅샷과 flush 시점 값을 비교해 차이가 있으면 자동으로 UPDATE를 생성합니다. flush는 보통 커밋 직전 자동으로 일어나지만, JPQL 쿼리 실행 직전이나 수동 호출로도 트리거될 수 있습니다.

### 1.4. 장단점 및 실무

이 덕분에 엔티티를 일반 객체처럼 다뤄 동기화를 JPA에게 위임할 수 있습니다. 단, 1차 캐시는 트랜잭션 범위 안에서만 유효하고 커밋 전엔 DB에 반영이 되지 않는다는 점을 기억하고 있어야 합니다.
