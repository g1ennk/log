# TCP 3-way handshake에 대해서 설명해주세요.

## 1. 요약

### 1.1. 결론

- TCP 3-way handshake는 TCP 프로토콜의 과정 중 하나로, 데이터 통신 전에 클라이언트와 서버가 세 번의 메시지 교환을 통해 서로의 초기 순서 번호를 동기화하고 양쪽 다 통신할 준비가 됐음을 확인하는 연결 수립 절차입니다.

### 1.2. 왜

- TCP는 양방향 신뢰성을 보장해야 하므로 클라이언트와 서버 각각의 순서 번호가 모두 동기화되어야 하고, 뒤늦게 도착한 옛 연결 요청이 의도치 않게 살아나는 것도 막아야 하기 때문입니다.

### 1.3. 원리

1. 먼저 클라이언트가 초기 순서 번호(ISN)를 담아 서버에 SYN를 보냅니다. (SYN_SENT)
2. 그 다음 서버는 자신의 ISN을 담은 SYN와 클라이언트의 ISN에 1을 더한 값을 ACK에 담아 "잘 받았다"는 확인 응답을 보냅니다. (SYN_RECEIVED)
3. 클라이언트는 서버의 ISN에 1을 더한 ACK를 돌려보내 서버의 SYNC를 확인합니다.

- 결과적으로 양쪽 모두 ESTABLISHED 상태가 되며 데이터 전송이 가능한 상태가 됩니다.

### 1.4. 판단 기준

- 따라서 handshake 비용을 최적화하고 싶다면 keep-alive나 커넥션 푸로 한 번 연 연결을 계속 재사용하거나,
- 아예 handshake가 없는 HTTP/3(QUIC)와 같은 프로토콜로 갈아타는 방법도 있습니다.
    - QUIC는 UDP 위에서 TCP와 같은 시퀀스 번호, ACK, 재전송, 흐름 및 혼잡 제어를 처리해 TCP와 동등한 신뢰성을 제공하는 별도의 프로토콜
