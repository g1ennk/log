# TCP 4-way handshake(연결 종료 과정)에 대해 설명해주세요

## 1. 요약

### 1.1. 결론

- TCP 4-way handshake는 연결을 끊을 때 데이터 유실이나 상태 불일치 없이 양쪽이 합의해 자원을 정리하는 종료 절차입니다.

### 1.2. 왜

- TCP는 연결지향 프로토콜이기 때문에 곧바로 연결을 끊어버리면 아직 전송 중인 데이터가 유실되거나, 한쪽만 끊긴 상태를 서로 다르게 인식할 수 있기에, 이를 질서 있게 종료하는 절차가 필요합니다.

### 1.3. 원리

1. 클라이언트가 FIN을 보내 종료를 요청합니다.
2. 서버는 ACK로 응답합니다. (서버는 남은 데이터를 마저 보냅니다)
3. 모든 데이터 전송이 끝났다면 서버도 클라이언트에게 FIN을 보내 종료를 알립니다.
4. 클라이언트가 마지막 ACK로 답하면서 연결이 닫힙니다.

- 여기서 3-way handshake와 다른 점은, 3-way에선 SYN+ACK를 하나의 패킷으로 합칠 수 있었지만, 종료는 서버가 남은 데이터를 처리해야 하므로 ACK와 FIN이 분리되어 하나의 단계가 더 추가됩니다.

### 1.4. 판단 기준

- 마지막으로 서버가 ACK를 보낸 후에는 패킷 유실과 재사용 충돌을 대비해 TIME_WAIT으로 잠시 대기합니다.
    - 단, Nginx나 Spring 서버처럼 연결을 많이 맺고 능동적으로 종료하면 TIME_WAIT 소켓이 쌓여 포트가 고갈될 수 있습니다.
    - 이런 경우 keep-alive로 종료 빈도를 줄이는 것도 하나의 해결 방법입니다.
