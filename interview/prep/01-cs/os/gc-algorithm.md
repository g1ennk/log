# GC 알고리즘은 어떤 것이 있나요?

## 1. 요약

### 1.1. 결론

- GC 알고리즘들은 Stop-The-World(STW, GC를 실행하기 위해 JVM이 애플리케이션의 모든 스레드 작업을 멈추는 시간)와 처리량 사이의 트레이드오프를 서로 다르게 배분한 전략들이다.

### 1.2. 왜

- 힙이 커지고 응답 속도 요구가 높아지면서, 단순히 메모리를 회수하는 걸 넘어 STW 시간을 얼마나 짧고 예측 가능하게 만드느냐가 GC 선택의 핵심 기준이 됐다. 작은 힙과 대용량 힙, 처리량 우선과 지연 우선을 하나의 알고리즘으로 동시에 만족시킬 수 없어서 여러 GC가 발전해왔다.

### 1.3. 원리

- Serial GC는 단일 스레드로 동작해 소규모 힙엔 적합하지만 STW가 길다.
- Parallel GC는 Young 영역을 멀티 스레드로 처리해 처리량을 개선했다.
- CMS GC는 지연 시간을 줄이려 했으나 단편화 문제로 폐지됐다.
- G1 GC는 region 기반으로 개선해 Java 9부터 default로 처리량과 지연 균형을 맞췄다.
- 대비축: 뒤로 갈수록 STW는 줄이는 대신 CPU·구현 복잡도를 더 쓴다.

### 1.4. 판단 기준

- 힙이 작고 코어 1개인 환경 -> Serial GC
- 대용량 힙에서 지연이 중요한 서비스엔 ZGC 같은 저지연 GC
