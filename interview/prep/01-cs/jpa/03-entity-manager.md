# EntityManager에 대해 설명해주세요.

## 1. 요약

### 1.1. 결론

EntityManager는 엔티티의 생성, 조회, 수정, 삭제 같은 영속성 작업을 처리하는 JPA의 핵심 API로, 애플리케이션 코드와 영속성 컨텍스트와 데이터베이스 사이를 이어주는 창구입니다.

### 1.2. 왜

JPA를 쓰는 애플리케이션은 엔티티를 저장하고 조회할 때마다 매번 직접 SQL을 작성하지 않고자 하는데, 엔티티 객체를 넘기면 그에 맞는 SQL을 생성하고 실행해 결과를 다시 객체로 매핑해주는 창구가 필요해 JPA는 EntityManager 인터페이스로 정의했습니다.

### 1.3. 원리

EntityManager는 애플리케이션 전체에서 하나만 만들어지는 EntityManagerFactory가 필요할 때마다 생성해내는 가벼운 객체로, 보통 트랜잭션 단위로 새로 만들어 쓰고 끝나면 버립니다. EntityManagerFactory는 커넥션 풀 초기화처럼 비용이 커 애플리케이션당 하나만 공유하는 반면, EntityManager는 그 팩토리가 매번 찍어내는 트랜잭션 단위 객체라는 점이 둘의 차이입니다.

### 1.4. 장단점 및 실무

EntityManager는 내부에 영속성 컨텍스트라는 가변 상태를 가지고 있어 스레드 안전하지 않기 때문에 여러 스레드가 하나의 인스턴스를 공유하면 데이터 정합성이 깨질 위험이 있는데, 이는 스프링이 실제 EntityManager 대신 프록시를 주입해 현재 트랜잭션에 바인딩된 진짜 EntityManager를 트랜잭션 범위에 맞춰 자동으로 생성해주고 종료해주기 때문에 싱글톤 빈에 주입받아도 동시성 문제 없이 생명주기를 신경 쓰지 않고 사용할 수 있습니다.
