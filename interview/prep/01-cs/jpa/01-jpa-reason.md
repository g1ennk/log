# JPA를 사용하는 이유를 설명해주세요.

## 1. 요약

### 1.1. 결론

JPA는 자바 객체와 관계형 데이터베이스 사이의 패러다임 불일치를 자동으로 매꿔주는, 자바 진영의 ORM 표준입니다.

### 1.2. 왜

JDBC를 직접 쓰면 SQL 작성과 결과를 객체로 매핑하는 반복 코드를 매번 손으로 작성해야 하는데, JPA는 엔티티에 매핑 정보만 선언해두면 이 반복 작업을 자동화해 해결합니다.

### 1.3. 원리

엔티티 클래스에 애노테이션을 테이블이나 컬럼 매핑을 선언하면 JPA 구현체가 저장, 조회, 수정, 삭제에 필요한 SQL을 상황에 맞게 자동 생성하고, 영속성 컨텍스트가 엔티티의 변경을 추적해 트랜잭션 커밋 시점에 변경된 내용만 반영해주기 때문에 별도의 update 쿼리를 작성하지 않아도 변경 감지가 이뤄집니다.

### 1.4. 장단점 및 실무

컬럼 하나가 추가돼도 매핑된 필드 하나만 추가하면 돼 생산성과 유지보수성은 크게 좋아지지만, 자동으로 생성되는 SQL을 제대로 파악하지 못하면 N+1처럼 의도치 않은 성능 저하가 쉽게 발생합니다. 따라서 실무에서는 쿼리를 로그로 항상 확인하고, 복잡한 통계나 집계 조회는 JPQL이나 네이티브 쿼리로 직접 작성하는 방식을 병행합니다.
