# GC 알고리즘은 어떤 것이 있나요?

## 1. 요약

### 1.1. 정의

- GC 알고리즘들은 Stop-The-World(STW, GC를 실행하기 위해 JVM이 애플리케이션의 모든 스레드 작업을 멈추는 시간) 시간과 처리량 사이의 트레이드오프를 다르게 배분한 전략들이다.

### 1.2. 원리

- Serial GC는 단일 스레드로 동작하며 소규모 힙엔 적합하지만 STW가 길다.
- Parallel GC는 Young 영역을 멀티 스레드로 처리해 처리량을 개선했다.
- CMS GC는 지연 시간을 줄이고자 했으나 단편화 문제로 폐지되었다.
- G1 GC는 region 기반으로 개선하여 Java 9부터 default로 처리량과 지연 균형을 맞췄다.

### 1.3. 실무

- 힙이 작고 코어 1개인 환경 -> Serial GC
- 대용량 힙에서 지연이 중요한 서비스엔 ZGC 같은 저지연 GC

## 2. 개념

### 2-1. 배경

- JVM의 가비지 컬렉터는 **처리량**과 **지연 시간**이라는 두 목표 사이에서 균형을 잡기 위해 계속 발전해 왔다.
    - 애플리케이션이 다루는 힙이 커지고 응답 속도에 대한 요구가 높아지면서, 단순히 메모리를 회수하는 것을 넘어 Stop-The-World 시간을 얼마나 짧고 예측 가능하게 만드느냐가 GC 알고리즘 선택의 핵심 기준이 되었다.
        - Stop-The-World란, GC를 실행하기 위해 JVM이 애플리케이션의 모든 스레드 작업을 멈추는 시간을 의미한다.

### 2-2. 초기 GC 계열: Serial, Parallel, CMS

1. Serial GC
    - JDK에 처음 도입된 가장 단순한 컬렉터로, 단일 스레드로 동작하기 때문에 GC가 일어나는 동안 애플리케이션이 완전히 멈춘다.
    - 힙이 작고 CPU 코어가 하나뿐인 환경에는 유효하지만, 서버 환경에서는 STW 시간이 가장 길다는 한계가 있다.

2. Parallel GC
    - Serial GC에 한계를 개선해 Young 영역 수집을 멀티 스레드로 처리해 Java 5-8까지 default GC로 쓰였다.
    - 높은 처리량에 초점을 맞춰 **Throughput GC**라고도 불렸다.

3. CMS(Concurrent Mark-Sweep) GC
    - 애플리케이션 스레드와 동시에 실행되어 STW 시간을 최소화하려 시도한 컬렉터이다.
    - 다만 메모리 압축을 수행하지 않아 단편화가 누적되고 CPU 사용량도 높다는 단점이 뚜렷했고, Java 9에서 deprecated된 뒤 14에서 완전히 제거되었다.
    - 중요한 건 CMS의 실패 경험이 이후 G1 GC 설계에 region 기반 점진적 회수라는 방향으로 직접 반영되었다는 것이다.

### 2-3. G1 GC: region 기반 구조

- Java 9부터 default GC로 채택된 G1(Garbage First) GC는 힙 전체를 균일한 크기의 region으로 잘게 나누고, 각 region을 논리적으로 Young 또는 Old 영역으로 유동적으로 배정한다.
    - GC 대상이 많은 region부터 우선 회수하기 때문에 **garbage first
      **라는 이름이 붙었고, 덕분에 힙 전체를 한 번에 정리하지 않고도 짧고 예측 가능한 pause time을 유지할 수 있다.

### 2-4. 저지연 GC: ZGC와 Shenandoah GC

- 힙 크기가 수십-수백 GB에 달하는 대규모 서비스에서는 G1 GC의 pause time(휴지 시간)조차 부담될 수 있다.
    - 이에 따라 10ms 이하의 STW를 목표로 하는 ZGC와 Shenandoah GC가 Java 11과 12부터 각각 도입되었다.
- 두 GC 모두 마킹과 압축 같은 무거운 작업을 대부분 애플리케이션 스레드와 동시에 수행해 지연 시간을 극단적으로 낮추지만, 그만큼 CPU 자원을 더 많이 소비해 처리량 측면에서는 G1보다 불리할 수 있다.

### 2-5. 실무에선?

- GC는 힙 크기와 서버 스펙에 따라 자동으로 결정되기도 한다.
    - OpenJDK는 CPU 코어 2개 이상, 메모리 2GB 이상인 환경을 Server-Class Machine으로 인식해 G1 GC를 기본으로 선택한다.
    - 단, 조건을 충족하지 못하면 Serial GC가 선택된다.
- 따라서 소규모 컨테이너 환경에서 의도치 않게 Serial GC가 동작하고 있지 않은지 확인하는 것도 점검 포인트 중 하나이다.
